# 第 6 课：安全边界、测试计划与上线前检查

## 1. 已实现的教学保护

- Web 服务绑定 loopback `127.0.0.1`，不开放外部网络接口。
- `ScopedTools` 构造阶段核对租户，不在允许租户的资产拒绝分析。
- `ScopedTools.call` 使用明确工具白名单，模型不能执行任意 Java 方法。
- `get_asset` / `get_vulnerabilities` 再次校验传入 IP == 本次授权 IP。
- 业务写操作不存在于模型工具列表中，草稿/审批由单独 HTTP 接口执行。
- 同一 `analysisId` 创建草稿具备内存级幂等；重复审批被拒绝。
- 工具次数最多 6 轮、HTTP 模型请求有超时、知识检索限制长度。

**但这些并不意味着生产安全合格**：`X-Lab-Token` / 固定审批码不提供真实身份认证，内存数据不可靠，日志未做脱敏和持久化，模型输入输出未实施成熟的提示词注入防护，缺少链路追踪/审计闭环。

## 3. 必须再补的测试

| 测试          | 输入或条件              | 预期                       |
|---------------|-------------------------|----------------------------|
| Tool 参数越权 | 模型要求读取其它 IP     | 拒绝且无泄露               |
| 提示词注入    | KB 文本包含「忽略规则」 | 不执行危险命令，不越权     |
| 工具失败      | 下游 API 返回 500       | 有清晰错误，不伪装成功     |
| 模型超时      | Ollama 服务不可用       | 失败可见，业务主链可选降级 |
| 并发分析      | 100 个模拟请求          | 资源池有界，稳定返回或限流 |
| 权限过期      | 审批期间用户权限被撤销  | 最终落库前重新校验         |
| 重复事件      | 同个扫描器消息投递两次  | 幂等处理                   |
| 知识库越权    | 他人租户文档被检索      | 强制过滤租户、资源权限     |
| 工单重试      | 创建工单 API 超时后重试 | 唯一业务键，不生成重复单   |

## 4. 生产上线的必补功能

- Spring Security + 真实 IdP (OAuth2/OIDC)，每个请求从认证 Token 推导可信身份和租户，而非相信 LLM 参数。
- MCP Server 的 HTTP 传输层使用认证，业务级 Tool 再做 ABAC/RBAC 授权；生产不以 `localhost` 当作全部安全边界。
- Prompt/KB/扫描结果当作不可信材料；限制 URL 访问、SSRF、防止提示词注入导致外部 exfiltration。
- 审批必须关联真实操作者、报告版本、工单业务键、审计事件；用户可拒绝并记录原因。
- MySQL 事务 + Outbox/MQ + 唯一约束保证持久化和跨服务一致性。
- 模型/工具链路 `traceId`、可观察指标、Token 成本与脱敏日志。
- 定期更新外部依赖及安全扫描，禁止将企业敏感原始数据直接传给未经批准的模型服务。

## 5. 关键安全事实

- Prompt 的「禁止越权」不是安全机制，只能当作模型行为提示。真正权限检查必须在 Tool / API 层。
- MCP 的 `tools/list` 和 `tools/call` 只是标准协议， **不意味着 MCP Server 自动具备企业授权能力**。
- Tool Calling 只能说明模型可以要求调用工具，不能代表模型有权直接执行业务写操作。
