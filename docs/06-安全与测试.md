# 第 6 课：安全边界、测试计划与上线前检查

## 1. 已实现的教学保护

- 离线核心、Spring Agent 和 MCP Server 默认绑定 `127.0.0.1`；Spring 的地址仍可被外部配置覆盖。
- 离线核心通过实验口令保护 API，并在 `ScopedTools` 构造时校验资产属于固定租户。
- 离线工具有显式白名单；参数必须仅含 Schema 声明的字符串字段，资产 IP 必须等于本次目标。
- Spring Agent 和 MCP Server 默认只允许 `192.0.2.10`；最终资产租户检查由核心 API 执行。
- 业务写操作没有注册为模型工具，草稿/审批由独立 HTTP 接口执行。
- 同一分析的草稿具有单 JVM 内存幂等性，重复审批被拒绝；全局 `synchronized` 保护状态变更，不适用于多节点一致性。
- 手写模型循环最多 6 轮 HTTP 请求，连接超时 8 秒、每次请求超时 75 秒；每轮可以有多个工具请求，没有累计工具次数/Token/整次分析耗时预算。
- 知识查询长度最多 200 个 Java 字符；工具最多返回 3 条，直接 REST 查询最多返回 5 条。
- 模型上游错误不会以成功报告保存，也不会把原始模型错误响应返回给客户端。

这些是教学保护，不是生产 IAM。Spring Agent/MCP 入口没有正式身份认证；审批码和 `approvedBy` 不能证明真实操作者身份；知识库为共享虚构资料，没有文档级授权；提示词与引用未实施服务端质量校验。

离线 HTTP 使用 8 个工作线程，但 `newFixedThreadPool` 的等待队列无界，不能宣称“资源池有界”。模型响应、分析历史和工单历史也未设置容量上限。Spring 示例不继承手写循环的 6 轮限制，REST 网关未显式配置业务超时。这些需要在生产化阶段处理。

## 2. 已可复现的自动化测试

```bash
./scripts/test-offline.sh
mvn -f spring-ai-workshop/pom.xml test
```

离线脚本包括：

1. `SelfTest`：JSON 往返、资产查询、资产范围与租户拒绝、工具白名单、参数类型及额外字段校验、检索、评分、轨迹、草稿幂等与审批状态。
2. `FakeModelTest`：两轮 OpenAI 兼容协议；fake 模型请求两个工具，Java 返回结果后模型输出最终回复。
3. `HttpApiTest`：独立子 JVM 的真实 HTTP API，覆盖口令、越权、未知资产、查询长度、评分、草稿/审批、模型 HTTP 错误/格式错误/空 choices，以及 6 轮循环上限。

Spring Maven 测试包括：

- `AgentControllerTest`（5 项）：MCP 回调注入、模型调用前越权拒绝、空问题拒绝、未连接 MCP 工具和模型失败映射。使用真实 `ChatClient`，模型与网关为 mock。
- `McpServerIntegrationTest`（2 项）：启动真实 Spring MCP Server，以 SDK 通过 Streamable HTTP 初始化、发现 3 个工具、调用工具和拒绝越权；核心 REST API 为本机 stub。

打包后，还可运行 `WorkshopSmokeTest`：真实离线核心 + 可执行 Spring JAR + fake Ollama，分别验证 local/MCP 两轮调用链。运行方法见 [09-核验记录.md](09-核验记录.md)。测试会关闭自己的子进程，HTTP/冒烟测试日志保存在 `offline-lab/target/`。

fake/mock 测试验证接入和协议，不代表真实模型选择、解释或引用质量。

## 3. 后续验证计划

| 测试 | 条件 | 预期与当前范围 |
|------|------|----------------|
| 真实模型工具选择 | 支持 tools 的真实 Ollama 模型 | 检查工具请求及结果，当前仅验证 fake 协议 |
| 提示词注入 | 文档含“忽略规则” | 验证解释和引文质量；危险能力目前不在工具列表中 |
| 下游失败与超时 | 核心 API 500、慢响应、连接中断 | 验证可见失败、超时和预算，覆盖实际工具路径 |
| 并发与容量 | 100 个模拟请求及持续积累报告 | 测量排队/内存，增加限流、有界队列和历史容量 |
| 权限过期 | 审批前撤销权限 | 引入真实 IAM 后在写入前重新授权 |
| 重复事件 | 扫描消息重复投递 | 引入消息消费后验证持久幂等 |
| 知识库权限 | 多租户私有文档 | 引入私有知识库后强制租户/文档过滤 |
| 外部工单重试 | 创建响应超时后重试 | 接入平台后用唯一业务键防重复 |

## 4. 生产化需补的能力

- Spring Security + 可信 IdP，身份和租户从认证上下文推导，每次资产/动作/文档访问均在服务端授权。
- MCP HTTP 的认证、Origin 校验和限流；本机绑定不能代替这些机制。参见 [MCP 2025-06-18 传输规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)。
- 将问题、KB 和扫描内容视为不可信输入；需要访问外部 URL 时限制目的地，防止 SSRF 和数据外传。
- 审批关联真实操作者、报告版本、业务键、审计事件和拒绝原因。
- 数据库事务、唯一约束和 Outbox/MQ 管理持久状态与跨服务补偿；消费者仍须处理重复投递。
- 端到端 `traceId`、模型/工具耗时与成本、失败轨迹和脱敏持久日志。
- 依赖更新与安全扫描，以及真实模型的工具选择、证据引用和输出质量评测。

## 5. 关键事实

Prompt 中的禁止越权只是行为提示，权限检查必须由工具/API 执行。MCP 标准化发现与调用，不自动提供企业授权。工具请求也不代表模型有权执行业务写操作。
