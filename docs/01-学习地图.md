# 第 1 课：四周学习地图

> 每一步都要求「操作验证 + 看懂源码 + 改动一个功能」，不要一开始就追求多 Agent。

## 第 1 周：理解系统本身（不需要大模型）

- Day 1：启动 `./scripts/run-offline.sh`；在网页完成单资产分析，找到 `toolTrace`。
- Day 2：阅读 `DemoData` 和 `ScopedTools`；画出 `get_asset` 的调用链。
- Day 3：把 `get_asset_ports(ip)` 加入白名单，并在 `schemas()` 中补充 JSON Schema；为越权参数写单测。
- Day 4：阅读 `AgentService` 的确定性评分；解释「风险评分」为何不能交给模型随意决定。
- Day 5：阅读 `TicketService`；理解草稿幂等、独立的人工审批请求和为什么 Agent 没有 `approve_ticket` 工具。
- 验收：解释 Tool/业务服务/模型的职责边界；`./scripts/test-offline.sh` 全绿。

## 第 2 周：真正的 Tool Calling

- Day 1：阅读 `ModelToolAgent` 的多轮消息结构（`FakeModelTest` 用两轮演示）；画出 `assistant.tool_calls -> tool -> assistant`。
- Day 2：运行 `FakeModelTest`，验证工具调度不是写死的假输出。
- Day 3：搭建 Ollama，下载支持 tools 的模型，运行 `mode=llm`。
- Day 4：故意要求模型查询另一台资产，观察工具级别如何拒绝越权。
- Day 5：在现有 6 轮模型请求上限之外，增加累计工具调用次数上限和 Token 预算策略；区分连接超时、单次请求超时与整次分析超时。
- 验收：抓到一次真实 `get_asset` + `get_vulnerabilities` 的工具轨迹；知道「LLM 不执行 Java 函数」。

## 第 3 周：Spring AI + 检索增强

- Day 1：用 Maven 启动 `spring-ai-workshop/agent-app`，对照手写版 Tool Calling。
- Day 2：比较 `@Tool`/`.tools(...)` 与手动传入 JSON Schema 的区别。
- Day 3：阅读 `DemoData.search`；用文档 `05-RAG设计与练习.md` 实现混合检索。
- Day 4：设计 `evidenceId` 与文档来源字段，检查不可信文档能否影响模型行为。
- Day 5：扩充知识库并比较改动前后的分析结果。
- 验收：模型回答能给出依据，且明确标注无法确认的信息。

## 第 4 周：MCP + 系统设计 + 简历准备

- Day 1：启动 MCP Server，理解 `tools/list`、`tools/call` 和适配原有 REST API。
- Day 2：使用 `mcp` profile 切换 Agent 工具来源；比较本地和远程链路。
- Day 3：模拟 MCP Server 不可用；观察启动连接失败和调用超时。当前没有自动回退，练习设计显式切换 local 的策略。
- Day 4：设计数据库持久化、队列、幂等键、租户隔离、可观测性。
- Day 5：完成一次 5 分钟演示：提出问题 → 工具调用 → 引用文档 → 人工审批。
- 验收：能回答「为什么不把所有工具都做成 MCP？」「MCP 与 Feign 区别是什么？」。

## 建议提交的 Git 里程碑

1. `feat: offline asset security analysis demo`
2. `feat: real tool calling with ollama`
3. `feat: spring ai request scoped tools`
4. `feat: mcp read-only facade`
5. `test: tenant isolation and approval flow`

建议在每个里程碑附 `README` 截图、测试输出及一次失败案例，不要把尚未做完的功能写成正式项目成果。
