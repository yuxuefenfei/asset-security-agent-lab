# 第 8 课：演示与可验证的项目描述

本文描述 2026-10-22 的实际能力。演示前按 [README](../README.md) 构建与启动，验证状态见[核验记录](09-核验记录.md)。

## 演示脚本

1. 在工作台和资产中心展示默认租户 32 项资产，搜索、筛选与翻页；打开 `192.0.2.10`，说明数据来自虚构初始化记录。
2. 进入「安全分析」运行 demo，在报告详情展示评分、两条扫描记录、知识证据和成功工具轨迹。
3. 比较新增网关 `192.0.2.30` 的四条漏洞与无漏洞 `192.0.2.38`，说明规则取值及当前 RESOLVED 记录仍参与评分。
4. 主动创建草稿，修改保存并输入审批码；从工单列表重新打开，确认审批后只读。另开旧版本可演示 409。
5. 展示报告快照和文件库重启保留，不把它当成外部正式工单或真实漏洞修复。
6. 用 WorkflowSmokeIT 展示 Spring local / MCP 的真实三服务协议链路，并明确模型是 OpenAI 兼容假服务。具备实际模型验收记录后，再演示真实工具选择。

核心 llm 当前有工具 Schema 构造缺陷，不能直接把 README 里的模式入口展示成真实模型已验证。`mode=llm` 也不意味着模型主动使用了工具，必须检查 `origin=llm-request`。

## 常见追问

**规则分析和 Agent 有什么区别？**

demo 由 Java 固定编排和评分；手写模型循环及 Spring ChatClient 支持模型提出工具请求，由 Java 授权执行。现有假模型测试验证交互协议，真实模型选择和解释质量未评测。

**Tool Calling 和 MCP 的关系？**

Tool Calling 是模型发出工具请求的方式；MCP 统一外部工具描述、发现和调用。当前 local 通过 @Tool 转核心 REST，MCP 多一层协议适配，业务数据和授权仍由核心负责。

**租户隔离在哪里？**

核心通过服务端固定租户配置过滤资产、报告和工单，工具绑定目标 IP；Spring / MCP 默认还限制固定 IP。知识共享，没有文档授权。当前不是从真实用户身份派生的多租户 IAM。

**RAG 使用什么向量库？**

没有向量库。当前是 16 份训练文档的数据库关键词检索、编号词项加权和报告证据快照；pgvector、Embedding、混合检索和引文校验属于后续练习。

**工单怎样防重复？**

H2 的 analysis_id 唯一约束保证同一分析只生成一张草稿，编辑 / 审批使用版本条件更新。当前没有外部投递或 Outbox；未来增加 Outbox 仍需要外部幂等键与回执。

**评分为什么不交给模型？**

结构化结果由可测试的 Java 规则计算，模型辅助解释；自然语言可能与评分不一致。当前最高 CVSS 加暴露与重要性是教学启发式，并非生产风险模型。

**前端做了哪些工程化工作？**

Vue / TypeScript / Hash 路由拆分列表、详情与表单，共享 API 客户端、请求状态和业务展示；Java record / enum 派生 TS 类型并检查漂移，数据由后端分页，浏览器回归覆盖审批和页面状态。

## 可以使用的个人项目描述

完成复现并能解释限制后，可以按事实表述：

> 基于 Java 21、Spring Boot、MyBatis-Flex、H2 / Flyway 与 Vue / TypeScript 构建资产安全教学工作台，实现资产与知识查询、确定性评分、分析证据快照及版本化人工审批草稿。实现只读工具的参数 / 目标范围校验，编写手写工具循环与 Spring AI / MCP 适配的协议回归测试；以隔离数据和假模型验证 local / MCP 链路与跨页面流程。

如果修复 Schema 并完成真实模型验收，再补充真实模型名称、验证样本和结果。不要写成已完成真实扫描、生产 IAM、向量 RAG、Outbox 投递、亿级资产运行或可量化的漏洞识别准确率。
