## 5 分钟演示脚本

1. 展示虚构资产 `192.0.2.10`，解释数据源是受控的模拟扫描记录。
2. 在网页点击 demo 分析，展示 `toolTrace`，逐一定位到 Java `ToolSession`。
3. 安装并拉取模型后切换 Ollama 真实模式，检查 `origin=llm-request` 轨迹以证明模型请求了工具；演示模型不能访问其它租户。没有真实模型时用 fake 测试展示协议，并明确标注模拟。
4. 展示 `knowledgeEvidence` 和固定 `source`，强调不是模型编造的参考文档。
5. 创建草稿、预览并保存人工修改后输入审批码，重复创建草稿验证幂等，重复审批验证非法状态迁移被拒绝。
6. 最后从 `mcp` profile 演示同一工具接入不同协议层的技术选择。

## 常见追问

**Q：你做的是 AI Agent 还是传统规则引擎？**  
A：demo 模式确实是规则编排，用来验证业务与权限；真实 `llm` 模式使用支持 Tool Calling 的大模型调用注册工具，Java
调度外部调用。两种模式刻意分开，避免把固定脚本伪装成 Agent。

**Q：Tool Calling 和 MCP 有什么区别？**  
A：Tool Calling 是模型选择函数并发出调用请求的机制；MCP 统一外部工具发现与调用协议。MCP 工具仍可经由模型 Tool Calling
被选中，Java 决定授权与执行。

**Q：如何保障租户隔离？**  
A：离线版在创建工具前校验目标资产所属固定租户，资产工具执行时再验 IP 范围；Spring/MCP 示例使用固定 IP 白名单，最终资产租户检查由核心 API 完成。共享教学知识库没有文档级租户隔离。生产版应使用可信认证上下文和数据库租户隔离，不允许模型自己提供认证身份。演示版只做了固定租户和
IP 检查。

**Q：RAG 用的是什么向量库？**  
A：当前源码没有向量库，是关键词检索 + 来源引用的基础练习。计划升级 pgvector + 精确编号检索 + Embedding + 混合召回。不要谎称已经实现向量检索。

**Q：工单如何防重复？**  
A：当前 H2 工单表的 `analysis_id` 唯一约束与事务保证草稿幂等，编辑和审批使用版本条件更新；Outbox 保证事件可重试投递，消费者仍需幂等处理，Outbox
本身不保证只投递一次。

**Q：为什么不把风险评分直接交给大模型？**  
A：分级策略需可验证、稳定可复现。离线版的结构化评分由 Java 计算，模型辅助解释；模型自然语言仍可能与评分不一致，需人工复核。Spring 示例只返回模型答复，不计算结构化评分。高风险动作需要独立授权工作流。
