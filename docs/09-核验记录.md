| Spring 固定版本组合 | 编译、测试、可执行 JAR 打包通过 | Spring AI 1.1.0 + Spring Boot 3.5.7；不表示它们是最新版本 |
| 离线规则与工具约束 | 通过 | `SelfTest` 覆盖固定租户、目标范围、参数、评分、幂等和审批 |
| 手写模型工具循环 | 通过 | `FakeModelTest` 两轮协议：2 个工具请求、2 个结果、最终答复 |
| 离线 HTTP 与模型失败语义 | 通过 | `HttpApiTest` 验证真实 HTTP、审批、模型错误/无效响应、6 轮循环上限 |

| MCP Streamable HTTP | 2 项集成测试通过 | 真实 Spring Server + Java SDK；初始化、3 个工具发现、调用、越权拒绝；核心 API 为 stub |
| Spring local/MCP 完整链路 | 通过 | `WorkshopSmokeTest` 启动真实核心与两个 Spring 可执行 JAR，模型为 fake Ollama；每种模式 2 轮模型请求、3 个返回工具结果 |

## 2. 本次修正

1. **MCP 回调接入**：把 `ChatClient.tools(provider)` 改为 `toolCallbacks(provider)`；前者用于扫描普通对象上的 `@Tool` 方法，不能正确注册 MCP 提供的回调。
2. **启动命令**：改为 `mvn -f <子模块>/pom.xml spring-boot:run`，避免 `-am` 把运行目标应用到没有主类的父工程。
3. **错误语义**：离线模型阶段失败统一映射 502，不保存成功报告且不透传上游原始错误；Spring 增加越权 403、参数 400、已映射服务失败 502 的异常处理。
4. **参数约束**：离线工具执行层强制检查必选字符串字段和禁止额外字段；直接知识 REST 查询增加 200 字符上限；Spring 拒绝空 IP/问题。
5. **回环绑定与响应**：离线服务明确绑定 `127.0.0.1`，404 也返回一致的 `success:false`。
6. **运行与架构说明**：评分发生在模型调用前；轨迹区分 Java 固定预查询和模型请求；Spring 示例只返回答复，不生成离线结构化报告或审批记录。
7. **能力边界说明**：6 是模型请求轮数上限，单轮可调用多个工具；知识库共享，`training://` 为虚构来源；当前没有服务端引文校验和文档级租户隔离。
8. **教学文案**：修正 MCP 默认传输、工具名差异、STDIO 子进程、审批操作者、工单 ID 替换、已有检索加权及联合索引等表述；新分析开始时清除旧工单状态显示。
9. **验证状态**：删除当前环境“没有 Maven、无法构建”的过时结论，保留真实模型与生产能力的验证边界。

## 3. 复现命令

以下命令从仓库根目录执行，使用 JDK 21。默认实验口令和审批码只适用于本机教学。

Linux/macOS/Git Bash：

```bash
bash ./scripts/test-offline.sh
mvn -f spring-ai-workshop/pom.xml package
# 上面的离线脚本已编译该冒烟测试；它不会随离线测试自动执行
java -cp "offline-lab/target/test-classes:offline-lab/target/classes" lab.WorkshopSmokeTest
```

Windows PowerShell：

```powershell
# 本次机器的 JDK 21 路径；其他机器请替换为实际安装目录
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
java -version
mvn -version

./scripts/test-offline.ps1

mvn -f spring-ai-workshop/pom.xml package
if ($LASTEXITCODE -ne 0) { throw 'Spring 构建或测试失败' }
java -cp "offline-lab/target/test-classes;offline-lab/target/classes" lab.WorkshopSmokeTest
if ($LASTEXITCODE -ne 0) { throw 'Spring local/MCP 冒烟测试失败' }
```

上述测试仅使用自己创建的回环随机端口和子进程，结束后关闭服务。HTTP/冒烟日志位于 `offline-lab/target/`，Spring JUnit 报告分别位于子模块的 `target/surefire-reports/`。若执行环境禁止回环连接，需要允许本机网络后运行；这与测试断言失败不同。

## 4. 真实模型验收办法

真实模型不作为此次协议核验的前提。安装 Ollama 并拉取支持 tools 的模型后，按 README 分别执行离线 `llm`、Spring local 和 Spring mcp：

1. 检查实际工具请求及参数；离线版必须看到 `origin=llm-request`，不能只凭 `mode=llm` 或 Java 预查询轨迹认定模型用了工具。
2. 检查资产、漏洞和知识证据是否确实来自工具；自然语言中的编号、来源与风险解释仍需逐项核实。
3. 测试未知/跨租户目标、工具跨资产请求、无资料问题和模型服务中断；失败不能保存为成功分析。
4. 记录模型名称与版本、测试问题、调用轨迹、原始输出和耗时，再评价工具选择、引文和解释质量。

生产化工作仍按第 6、7 课推进：IAM、文档权限、持久化、真实审批身份、引文校验、并发容量与预算、可靠工单集成等目前不属于已实现能力。

## 5. 核对依据

- [Spring AI 1.1.0 ChatClient API](https://docs.spring.io/spring-ai/docs/1.1.0/api/org/springframework/ai/chat/client/ChatClient.ChatClientRequestSpec.html)：`tools(Object...)` 与 `toolCallbacks(ToolCallbackProvider...)` 是不同接口，并已与本地 1.1.0 JAR/源码核对。
- [Spring AI MCP Server 配置](https://docs.spring.io/spring-ai/reference/1.1/api/mcp/mcp-server-boot-starter-docs.html)：本仓库显式配置 `protocol: STREAMABLE`，不依赖默认传输。
- [Spring AI MCP Client 配置](https://docs.spring.io/spring-ai/reference/1.1/api/mcp/mcp-client-boot-starter-docs.html)：连接 URL 与 `/mcp` 端点分开配置，已用真实服务联通。
- [MCP 2025-06-18 传输规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)：STDIO 使用子进程；Streamable HTTP 支持 POST/GET，并要求 Origin 校验等保护。
- [Ollama Tool Calling](https://docs.ollama.com/capabilities/tool-calling)：工具定义、模型请求和工具结果组成多轮交互，模型本身不执行 Java。

## 6. 2026-10-13：离线核心迁移到 Maven

`offline-lab/pom.xml` 固定 Java 21 和 UTF-8，自动复制首页资源；JUnit 仅用于测试，应用运行时没有第三方依赖。产物为 `offline-lab/target/offline-lab.jar`，入口是 `lab.LabServer`。

本次使用 JDK 21.0.4 和 Maven 3.9.6 完成以下核验：

- `mvn -o -f offline-lab/pom.xml clean verify`：通过，三个原有自检由 `OfflineLabTest` 接入 JUnit，3 项测试、0 失败、0 错误。
- PowerShell 与 Bash 测试脚本：从 `docs/` 目录调用均通过，不依赖当前工作目录。
- PowerShell 与 Bash 运行脚本：从 `docs/` 目录在随机本机端口启动，首页返回 200，携带自定义实验口令的健康检查返回 `UP`；核验后关闭创建的进程。
- JAR 内容：含 `index.html` 和 `lab/LabServer.class`，清单声明 `Main-Class: lab.LabServer`，不包含 JUnit 或测试类。

Bash 命令统一用 `bash ./scripts/...` 调用，避免依赖检出的可执行位；`.gitattributes` 固定 `.sh` 为 LF，避免 Windows 换行影响脚本。首次构建仍需下载 Maven 插件和测试依赖；本次离线构建使用已有依赖缓存。HTTP 测试须允许本机回环连接。
