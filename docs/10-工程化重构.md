# 第 10 课：类型、持久化与人工审核的工程化重构

## 已确认的设计

三个服务统一使用 Java 21、现有 Spring Boot 3.5.7 和 Maven 根聚合工程；Spring AI 保持 1.1.0。核心使用 Spring MVC、MyBatis-Flex 1.11.8、H2 和 Flyway。H2、Flyway、Lombok 的版本由 Spring Boot BOM 管理。

- `lab-contract`：按资产、漏洞、知识、分析、工单、工具等功能维护 record DTO、API 枚举和响应契约，不依赖 Web 或持久化框架。
- `offline-lab`：业务核心；每个功能下按需分 `web`、`application`、`domain`、`persistence`，HTTP 控制器只调用应用服务。
- `spring-ai-workshop/agent-app`：配置、应用编排、核心 HTTP 客户端、请求范围工具和 Web 入口分包。
- `spring-ai-workshop/mcp-server`：配置与只读 MCP 工具分包，复用核心 API，不维护数据库副本。

固定的 HTTP 协议名与接口容量上限由 `LabProtocol`、`ApiConstraints` 集中定义；运行设置由经过校验的 `SecurityProperties`、`PolicyProperties`、`RiskProperties`、`ModelProperties` 和各服务的 `LabProperties` 管理。提示词位于资源目录。调整值导致矛盾阈值或不合法 URL 时应在启动阶段失败。

请求和响应使用 record；服务的 final 依赖使用 `@RequiredArgsConstructor`；PO 使用 `@Getter`、`@Setter`、`@NoArgsConstructor`。业务对象不再使用 `Map<String,Object>`。模型的动态函数参数和 JSON Schema 使用 `JsonNode`，与固定业务 DTO 分开。Java 协议字段使用驼峰命名，通过 `@JsonProperty` 保留外部协议的下划线字段。

## 数据模型与快照

| 表 | PO / Mapper | 责任 |
|---|---|---|
| `lab_asset` | `AssetPO` / `AssetMapper` | 资产与固定租户归属 |
| `lab_asset_port` | `AssetPortPO` / `AssetPortMapper` | 资产端口与唯一性 |
| `lab_vulnerability` | `VulnerabilityPO` / `VulnerabilityMapper` | 虚构扫描记录 |
| `lab_knowledge` | `KnowledgePO` / `KnowledgeMapper` | 共享教学知识文档 |
| `lab_analysis` | `AnalysisPO` / `AnalysisMapper` | 评分、说明及资产/漏洞类型化快照 |
| `lab_analysis_evidence` | `AnalysisEvidencePO` / `AnalysisEvidenceMapper` | 分析时实际使用的知识正文、来源及顺序 |
| `lab_tool_trace` | `ToolTracePO` / `ToolTraceMapper` | 参数、调用来源和结果数量快照 |
| `lab_ticket` | `TicketPO` / `TicketMapper` | 可审核内容、状态、版本与模拟审批信息 |

资产和漏洞的快照以 DTO 序列化的 JSON 保存在报告中；证据和轨迹分表保存。查询历史报告不会重新关联最新资产、漏洞或知识正文。记录 ID 使用稳定字符串；报告和工单使用 UUID，不再按当前集合大小生成工单 ID。

Flyway `V1__schema.sql` 建表并添加外键、唯一约束、状态与分数检查；`V2__training_data.sql` 插入原有虚构数据。已执行的迁移在重启时只验证，不重新覆盖业务数据。开发默认使用 `jdbc:h2:file:./data/asset-security`，测试使用隔离内存库或临时文件库。数据库文件已加入忽略规则。

运行脚本会切换到仓库根目录，数据库路径不依赖调用脚本时所在的目录。IDEA 运行 `lab.LabServer` 时也应将工作目录设为仓库根；需要其他路径时设置 `LAB_DB_URL` 为明确的绝对路径。

## 草稿审核与兼容例外

分析成功后用户主动生成草稿，页面展示关联资产、风险、证据、标题、整改建议、备注、创建时间及版本。标题、整改建议和备注可编辑，风险和证据只读。未保存修改时不能审批，审批后内容锁定。

- 数据库唯一约束保证同一 `analysisId` 只有一份工单，并发创建时返回同一份记录。
- 修改和审批通过版本条件更新；更新零行返回 `409 VERSION_CONFLICT`。
- 修改与审批在应用服务事务中完成；模型网络调用发生在数据库事务之外。
- 重新生成已审批草稿仍展示已审批状态，并保持审批按钮禁用。
- 新分析开始或选择历史报告时取消旧页面请求；响应必须属于当前报告和当前页面代次。

**唯一明确确认的请求兼容例外**：编辑和审批必须提交 `version`。旧审批路径和原有字段保留，缺少版本号返回 400，版本过期返回 409。客户端应先读取并审核当前版本，再提交审批。对已审批工单提交当前版本仍返回 400；用旧版本重试返回 409。

原有成功包装 `{success:true,data:...}`、业务字段、枚举 JSON 值和 ISO-8601 UTC 时间格式保留。错误响应增加 `code` 和 `traceId`；内部异常返回 500，模型上游失败返回 502，日志可通过请求编号定位。请求仍需 `X-Lab-Token`，首页和明确列出的静态资源无需口令。

## 列表与调用预算

新增 `/api/assets/page`、`/api/analyses/page`、`/api/tickets/page`，返回 `items/page/size/total`，页码从 1 开始，最大页大小默认 100，在数据库完成分页与稳定排序。旧资产、报告、工单数组接口保留，最多返回 `lab.policy.legacy-list-limit` 条；完整浏览使用分页接口。资产、漏洞和知识当前只有迁移脚本中的受控教学记录，没有对外新增扫描或导入接口。

关键词召回、原有编号权重与排序由数据库完成，结果数量在查询中限制。模型请求还限制轮数、工具次数、响应下载容量、单次与总超时及并发分析数量，超限不会保存成功报告。Spring Agent/MCP 到核心的 HTTP 客户端增加连接与读取超时。

## 构建和核验

从仓库根执行：

```bash
mvn clean verify
mvn spotless:apply
bash ./scripts/run-offline.sh
```

`verify` 包括共享契约测试、核心 HTTP/策略/并发测试、H2 文件重启测试、Spring Agent 测试、真实 MCP 协议测试、打包后的三服务 local/MCP 冒烟和 Java/POM 格式检查。APT 表定义由实体生成，位于 `target/generated-sources/annotations`，不提交、不手改。

浏览器回归使用 Node 20+、pnpm 与 Playwright；应用本身不需要 Node 或前端构建：

```bash
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm test:ui
```

浏览器测试自动启动打包后的核心 JAR，使用随机回环端口与内存库，验证草稿预览、编辑、审批、历史恢复、过期版本、陈旧响应隔离与文本转义，结束后关闭自己的服务。可通过 `LAB_BROWSER_CHANNEL=chrome` 或 `msedge` 使用已安装的浏览器。
