# 第 10 课：工程结构、持久化与审批

当前实现核对日期：2026-10-22。本文描述现有结构，运行步骤见 [README](../README.md)，当前测试证据见[第 9 课](09-核验记录.md)。

## 模块与契约

根 Maven 聚合工程使用 Java 21、Spring Boot 3.5.7、Spring AI 1.1.0；核心使用 Spring MVC、MyBatis-Flex 1.11.8、H2 和 Flyway。Node / pnpm 负责 Vue 前端构建，不属于服务运行时要求。

| 模块                          | 职责                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------- |
| lab-contract                  | 按资产、漏洞、知识、分析、工单、工作台与工具维护 record / enum、校验容量及协议头 |
| offline-lab                   | 核心业务、数据库迁移、工具循环和 Vue 静态资源                                    |
| frontend                      | 页面、共享交互、API 模块和从 Java 派生的 TS 契约                                 |
| spring-ai-workshop/agent-app  | ChatClient 编排、核心 HTTP 网关、请求范围工具与 Web 接口                         |
| spring-ai-workshop/mcp-server | MCP 工具适配，复用核心 REST API                                                  |

Java 业务 DTO 不暴露持久化 PO；PO 用 Getter / Setter / NoArgsConstructor，服务采用 final 依赖与构造注入。动态模型参数用 JsonNode。LabProtocol、ApiConstraints 集中协议名与固定容量；运行设置用经过校验的 ConfigurationProperties。

前端 contracts.ts 由 `scripts/generate-contracts.mjs` 从 Java record / enum、容量与协议名称派生；构建校验文件漂移。项目尚未提供 OpenAPI 文档 / 自动客户端生成，不能将此描述为完整 OpenAPI 工具链。

## 核心包与调用链

| 包                                     | 当前职责                                                   |
| -------------------------------------- | ---------------------------------------------------------- |
| lab.controller                         | 资产、漏洞、知识、分析、工单、工作台、健康与工具 HTTP 入口 |
| lab.service                            | 业务编排、授权、Dashboard 聚合、RiskPolicy 与 PagePolicy   |
| lab.dao                                | 8 个 Mapper、AnalysisRepository 与 TicketRepository        |
| lab.entity                             | 8 个 PO；APT 表定义生成在 lab.entity.table                 |
| lab.tools                              | 工具定义、执行会话和短事务快照工厂                         |
| lab.client / lab.dto                   | 模型 HTTP、下载容量与协议消息                              |
| lab.config                             | 类型化配置、客户端与提示词等 Bean                          |
| lab.enums / lab.exception / lab.filter | 内部错误、统一响应、口令与请求容量                         |

资产 / 漏洞 / 知识使用 Controller → Service → Mapper；分析 / 工单使用 Service → Repository → Mapper，Repository 负责组合快照持久化或版本化操作。Dashboard 由 Service 对 Mapper 执行按租户 count。

资产页查询分页在数据库执行，但当前每个返回资产单独读取 ports；本项目未做端口批量预取或分页查询次数性能优化。

## 数据模型与事务

| 表                    | 作用                               |
| --------------------- | ---------------------------------- |
| lab_asset             | 固定租户资产                       |
| lab_asset_port        | 关联端口，资产 / 端口唯一          |
| lab_vulnerability     | 模拟扫描记录与状态                 |
| lab_knowledge         | 共享教学正文 / 来源                |
| lab_analysis          | 风险 / 模式、资产与漏洞 JSON 快照  |
| lab_analysis_evidence | 使用时的知识正文 / 来源与次序      |
| lab_tool_trace        | 成功工具调用、参数、来源与结果数   |
| lab_ticket            | 草稿内容、版本、状态与模拟审批信息 |

ToolSessionFactory 使用短只读可重复读事务固定资产 / 漏洞；模型网络请求在事务外。AnalysisRepository 在事务中保存报告、证据与轨迹；读取历史报告不会重查最新资产、漏洞或正文。

TicketRepository 独立事务插入草稿；analysis_id 唯一，竞争失败后读取已存在记录。编辑 / 审批在服务事务中按版本条件更新，成功递增 version。审批记录 DRAFT → APPROVED；没有外部创建正式工单步骤。

## 迁移与默认库

| 迁移                           | 内容                                        |
| ------------------------------ | ------------------------------------------- |
| V1__schema.sql                 | 8 表、外键、唯一约束、状态 / 分数检查与索引 |
| V2__training_data.sql          | 原有 3 资产、4 漏洞及对应训练资料           |
| V3__expanded_training_data.sql | 追加 35 资产、96 漏洞、100 端口与 12 份知识 |

V1–V3 完成后的总数见[数据集](12-模拟数据集.md)。已执行迁移只做校验，不重置修改；新版本必须另加迁移，不改旧文件校验和。

默认 `jdbc:h2:file:./data/asset-security`；运行脚本会切到仓库根，IDEA 和直接 JAR 应保持同一工作目录，或配置绝对 LAB_DB_URL。数据库文件被 Git 忽略。测试使用隔离内存库或临时文件库。

## API、分页与兼容

核心成功 / 错误包装和 ISO-8601 UTC 时间保留；前端按 Asia/Shanghai 展示。未知方法 / 路径在认证后返回 404；业务缺失记录当前通常返回 400。

分页 API 覆盖资产、分析、工单和知识目录，默认 size=20、上限默认 100，稳定排序。列表筛选在数据库完成，旧数组接口受 legacy-list-limit 限制。资产漏洞接口仍按单资产返回全部受控记录，没有扫描导入和分页；当前种子每资产最多 4 条，不是可扩展扫描系统。

审批和编辑必须带 version，缺少返回 400、过期返回 409；已审批当前版本再次处理返回 400。前端未保存不能审批，409 后暂停编辑 / 审批直到主动重载。

## 前端打包与验证

generate-resources 调用 scripts/build-frontend.mjs，冻结安装、契约检查、vue-tsc 与 Vite build 后，将 frontend/dist 复制到核心类路径 static。旧原生页面仍保留在资源源码目录，但在 Maven 中排除，不参与当前 JAR 页面。

完整验证运行 `mvn verify`，浏览器回归和格式分别为 `pnpm test:ui`、`pnpm format:check`。已有可用 frontend/dist 且前端未变时可用 `-Dfrontend.skip=true`，全新环境不能依此获得静态页面。

已知核心工具 Schema 和 Agent 默认模式配置问题见[核验记录](09-核验记录.md)；真实身份、文档授权、完整审计、外部投递、生产数据库和向量检索仍为后续工作。
