# 第 7 课：升级路线与运行排查

依据 2026-10-22 的实现。当前已有 Vue 工作台、H2 持久化、Flyway、数据库分页、类型化契约、版本化工单、固定租户隔离及核心模型预算；这些不是待从零实现的功能。

## 建议推进顺序

### 1. 补齐真实模型接入证据

先修复核心工具 parameters 的 JSON Schema 构造并增加结构断言，再联调真实 Chat Completions 服务。记录模型版本、工具选择、拒绝路径、引文、耗时与失败样本；现有假模型只验证循环与工程行为。

Spring Agent 已使用 OpenAI 兼容 starter；明确选择 local 或 mcp，配置根地址、模型和密钥。不要把核心 LLM_API_URL 的完整接口地址直接当作 Agent LLM_BASE_URL。

### 2. 接入可信身份与真实数据

- 将配置的固定租户改为来自认证上下文的租户 / 操作者，按业务边界实施 RBAC / ABAC、文档授权及审计。
- 为真实扫描输入设计规则、服务 / 端口实例、来源和时间的幂等键，拒绝把模型输出当扫描事实。
- 评估生产关系库及迁移方案、索引与恢复演练；当前已有 H2 外键、唯一约束和快照，不能只切连接串就宣称生产就绪。
- 若选择向量检索，按[第 5 课](05-RAG设计与练习.md)增加精确元数据、版本、分块、授权与评测。

### 3. 可靠分析任务

- 将耗时同步分析按实际需要改为任务 API，持久化状态、失败、重试、开始 / 结束时间及模型版本。
- 在已有轮数 / 次数 / 下载 / 时间上限之外增加 Token / 费用预算、限流、可观测性和经过验证的重试策略。
- 需要事件解耦时再引入消息队列，消费者保持幂等。
- 完整记录失败与拒绝轨迹；当前成功报告内的 toolTrace 不是审计账本。

### 4. MCP 接入治理

保留原有 Service / REST / SDK，MCP 只包装确有跨客户端复用需求的稳定工具。增加认证授权、工具版本、Schema 契约、速率限制、审计及故障策略；按组织和权限边界决定服务拆分，不按工具数量机械拆分。

### 5. 外部工单与复检

人工确认当前版本后才投递正式工单。设计待投递状态、Outbox / 重试、外部业务幂等键与投递回执；Outbox 不是恰好一次承诺。闭环完成需要真实扫描复检或人工验证，APPROVED 不能代表已修复。

复杂任务 / 工单状态机应按真实流程另行定义。当前只有分析成功 ANALYZED 与工单 DRAFT → APPROVED，没有排队、执行整改、投递和关闭状态。

## 常见运行问题

| 现象                                 | 当前排查依据                                                                              |
| ------------------------------------ | ----------------------------------------------------------------------------------------- |
| Maven / Node / pnpm 不存在或版本不符 | 构建需 JDK 21、Maven 3.9+、Node ^22.18.0 或 >=24.12.0、pnpm 10.32.1；运行 JAR 才只需 Java |
| Maven 离线但前端仍需网络             | Maven -o 不覆盖 pnpm；先填充两套依赖缓存，冻结安装仍会检查依赖                            |
| Windows 无法重打包 / clean           | 停止占用对应 JAR 的本机服务再构建；不要通过删 H2 库解决                                   |
| 页面可开但 API 403                   | 在实验设置同步核心 LAB_API_TOKEN；静态入口可匿名不代表 API 可匿名                         |
| 前端开发无法连核心                   | 启动 Vite 的终端设置 LAB_DEV_API_URL；当前 config 没有用 loadEnv 读取 .env 中的代理变量   |
| 数据库出现两个副本                   | 相对文件 URL 依赖工作目录；直接 JAR / IDEA 使用仓库根，或指定绝对 LAB_DB_URL              |
| H2 文件被占用                        | 嵌入式文件库不应由两个服务同时打开；测试使用各自内存 / 临时库                             |
| Agent 启动提示模型配置缺失           | 设置 LLM_BASE_URL、LLM_MODEL、LLM_API_KEY；当前后端不会自动读前端 .env                    |
| Agent 请求提示 MCP 工具未连接        | 裸配置为 mcp 且 Client 关闭；local 显式 --lab.tool-backend=local，MCP 使用 mcp profile    |
| MCP 连接失败                         | 顺序是核心 8080 → MCP 8082 → Agent 8083 的 mcp profile；两个 Agent 不可同时占 8083        |
| Agent 工具不能查新增资产             | 默认 allowed-ip 仅 192.0.2.10；Agent 和 MCP 配置需一致，核心仍检查租户                    |
| Ollama 连接失败                      | 检查模型服务与已拉取模型；当前 Spring 集成使用 OpenAI 兼容接口，不读取旧 OLLAMA_* 配置    |
| 核心 llm 被真实模型拒绝              | 检查已知 parameters Schema 缺陷；fake 通过不代表真实兼容                                  |
| 浏览器超时 / 切页                    | 从报告列表确认任务是否已保存，再决定是否重试；前端取消不保证后端回滚                      |

`spring-ai.version=1.1.0`、`Spring Boot=3.5.7` 是仓库固定组合，不声明最新。升级应对照目标版本文档并重新运行 Java / TS 契约、类型、格式、浏览器和打包调用链测试。完整命令及当前结果见[核验记录](09-核验记录.md)。

项目没有提供生产部署、进程守护、TLS、监控或正式备份恢复方案；这些需要跟随部署目标补齐。
